# test — 효과 측정

Caveman과 RTK가 실제로 토큰과 비용을 줄이는지 측정하는 도구입니다.

> 확인 기준: Claude Code 2.1.292 · RTK 0.51.0 · caveman v2.7.0 · 2026-10-07

도구가 스스로 보고하는 절약량(`rtk gain`, `caveman stats`)은 청구액이 아닙니다. 여기서는 Claude Code가 돌려주는 **실제 사용량**(`claude -p`의 JSON 결과, `ccusage`)으로만 판단합니다.

## 파일

| 파일 | 역할 |
|---|---|
| `ab_test.sh` | 같은 작업을 4가지 조건으로 반복 실행하고 결과 JSON을 저장 |
| `summarize.py` | 결과 폴더를 읽어 조건별 평균과 기준(A) 대비 차이를 표로 정리 |
| `results/` | 실행 결과. 로컬 경로·세션 정보가 들어 있어 git에 올리지 않음 (`.gitignore`) |

## 방법 1: A/B 실험 (정확)

같은 저장소에서 같은 작업을 조건만 바꿔 돌립니다.

| 조건 | RTK | Caveman | 끄고 켜는 방법 |
|---|---|---|---|
| A 기준 | 끔 | 끔 | `--settings '{"disableAllHooks":true}'` (훅 전체 끔) |
| B | 켬 | 끔 | 설정 그대로 |
| C | 끔 | 켬 | 훅 끔 + 프롬프트 맨 앞에 `/caveman full` |
| D | 켬 | 켬 | 프롬프트 맨 앞에 `/caveman full` |

### 실행

```bash
cd agent-token-lab

# 1. 먼저 실행할 명령 확인
bash test/ab_test.sh --repo <git 저장소> --model sonnet --dry-run

# 2. 빠른 시험 (조건 4개 × 1회 = claude -p 4번)
bash test/ab_test.sh --repo <git 저장소> --runs 1 --model sonnet

# 3. 본 측정 (조건 4개 × 5회 = 20번)
bash test/ab_test.sh --repo <git 저장소> --runs 5 --model sonnet
```

결과는 `test/results/<날짜-시간>/`에 저장되고, 마지막에 요약 표가 출력됩니다. 나중에 다시 정리하려면 `python3 test/summarize.py test/results/<폴더>`를 실행하세요.

### 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--repo <경로>` | 현재 폴더 | 작업할 git 저장소 |
| `--task "<작업>"` | 저장소 구조·git log 요약 | 모든 조건에 똑같이 줄 작업 |
| `--runs <N>` | 3 | 조건마다 반복 횟수 |
| `--model <모델>` | 계정 기본값 | `sonnet`, `opus`, `haiku` 등. 비교는 같은 모델끼리 |
| `--max-turns <N>` | 20 | 실행 1회의 최대 턴 수 |
| `--conditions "A C"` | `"A B C D"` | 돌릴 조건만 고르기 |
| `--out <폴더>` | `test/results/<날짜-시간>` | 같은 폴더를 주면 결과를 이어서 쌓음 |
| `--dry-run` | | 실행할 명령만 출력 |
| `-y`, `--yes` | | 확인 질문 없이 진행 |

### 결과 읽는 법

| 열 | 뜻 | 주로 보는 도구 |
|---|---|---|
| **환산비용\*** | 컨텍스트 × 0.1 + 출력 × 5 (입력 토큰 환산). 캐시가 늘 따뜻하다고 가정해 캐시 영향을 뺀 값. **조건 비교는 이 열로 함** | 전체 판단 |
| 컨텍스트 | 입력 + 캐시쓰기 + 캐시읽기. 모델이 처리한 전체 입력 | RTK (명령 출력이 줄면 함께 줄어야 함) |
| 비용($) | `total_cost_usd`. 실제 청구 추정. 그 회차가 캐시를 새로 썼는지(약 $0.1) 다시 읽었는지(약 $0.02)에 크게 좌우됨 | 참고만 |
| 캐시쓰기·캐시읽기 | 컨텍스트를 캐시에 쓰고 다시 읽은 토큰. 비용의 대부분 | RTK (명령 출력이 줄면 함께 줄어야 함) |
| 출력 | 모델이 쓴 토큰 | Caveman |
| 턴 | 모델 요청 횟수. 늘면 비용도 늘어남 | RTK (정보가 빠지면 명령을 다시 돌려 늘 수 있음) |

괄호 안 숫자는 A(기준) 대비 차이입니다.

**왜 비용($)으로 비교하지 않나:** 같은 작업이라도 캐시를 새로 쓴 회차는 다시 읽은 회차보다 약 5배 비쌉니다. 어느 회차가 캐시를 새로 쓸지는 앞 실행에 달려 있어서, 5회 평균으로도 이 영향이 상쇄되지 않았습니다(2026-10-08 측정에서 C가 +66%, D가 −51%로 나왔으나 환산비용으로는 둘 다 약 −7%). 0.1과 5는 Claude 모델 대부분의 가격 비율(캐시 읽기 = 입력의 0.1배, 출력 = 입력의 5배)입니다.

### 작업 고르기

- **RTK 효과를 보려면** 셸 출력이 큰 작업을 고르세요. 테스트 실행, 긴 `git log`, 빌드 같은 것입니다. 기본 작업은 셸 출력이 작아서 RTK 차이가 거의 나지 않습니다.
  ```bash
  bash test/ab_test.sh --repo <저장소> --model sonnet \
    --task "git log -50 --stat 결과를 보고 최근 변경 경향을 5줄로 요약해 줘. 파일은 수정하지 마."
  ```
  셸 명령을 추가로 쓰는 작업이라면 `ab_test.sh`의 허용 도구 목록(`--allowedTools`)에 해당 명령을 넣으세요. 허용되지 않은 명령은 거부되고, 요약표 "참고"에 권한 거부 건수가 나옵니다.
- **파일을 고치지 않는 작업**을 고르세요. 허용 도구도 읽기 전용(`Read`, `Grep`, `git`, `ls` 등)으로만 열어 두었습니다.

### 주의

- **반복 횟수:** 같은 조건이라도 답변 길이와 턴 수가 매번 다릅니다. 1회 결과는 시험용이고, 판단은 5회 이상 평균으로 하세요.
- **실행 순서:** 같은 폴더에서 연달아 돌리면 뒤쪽 실행이 앞 실행의 캐시 덕을 볼 수 있습니다. 그래서 회차마다 조건 순서를 한 칸씩 돌립니다(A B C D → B C D A → …).
- **RTK.md는 모든 조건에서 로딩됩니다.** `disableAllHooks`는 훅만 끄기 때문에, `~/.claude/CLAUDE.md`의 `@RTK.md`(약 100토큰)는 A·C에서도 들어갑니다. 차이는 작지만 완전한 "RTK 없음"은 아닙니다.
- **다른 훅도 같이 꺼집니다.** RTK 말고도 사용자 훅이 있다면 A·C에서 함께 꺼집니다.
- **Caveman은 한 번의 호출로 켭니다.** 켜는 호출과 작업 호출을 나누면 세션 시작 비용이 두 번 들어 C·D가 부당하게 비싸게 나옵니다. 2026-10-07 시험에서 이 방식이 +156%로 나와 지금 방식으로 바꿨습니다.
- **비용:** 기본 모델이 Opus 계열이면 1회에 $0.1 이상 들 수 있습니다. 본 측정은 `--model sonnet`을 권장합니다.

## 방법 2: 날짜별 비교 (간단, 대략)

`ccusage`는 로컬 로그를 날짜별로 보여줍니다. 그래서 설치 전 기록도 나중에 볼 수 있습니다.

```bash
npx ccusage@latest claude daily --since 2026-09-15
npx ccusage@latest claude session --since 2026-09-15
```

- 설치일 전후로 나눠서 **세션당 평균**을 비교하세요. 하루 작업량이 날마다 달라 합계는 비교가 안 됩니다. 설치한 날은 빼세요.
- `ccusage`는 어느 세션에서 `/caveman`을 켰는지 모릅니다. 대략적인 경향만 볼 수 있습니다.

## 측정 기록

### 1. Caveman 중심 (2026-10-08)

- 모델 sonnet, 조건 4개 × 5회, 저장소 `ai-prompt-library`(커밋 8개), 기본 작업(저장소 구조·git log 요약)
- Claude Code 2.1.292, RTK 0.51.0, caveman v2.7.0

| 조건 | 환산비용* | 컨텍스트 | 출력 | 턴 | 비용($, 참고) |
|---|---|---|---|---|---|
| A 기준 | 9,912 | 67,983 | 623 | 2.0 | 0.0452 |
| B RTK | 10,216 (+3%) | 67,865 (−0%) | 686 (+10%) | 2.2 | 0.0588 |
| C Caveman | **9,204 (−7%)** | 70,288 (+3%) | **435 (−30%)** | 2.0 | 0.0749 |
| D 둘 다 | **9,123 (−8%)** | 70,048 (+3%) | 424 (−32%) | 2.0 | 0.0223 |

- **Caveman:** 출력은 −30%로 크게 줄었지만, 스킬 본문이 컨텍스트에 +3% 더해집니다. 그래서 실제 효과는 **약 −7%**입니다. 비용의 대부분이 컨텍스트라서, 출력을 줄여도 전체 효과는 한 자릿수에 그칩니다. JetBrains 측정(출력 −8.5%, 작업당 비용 약 −10%)과 비슷한 수준입니다.
- **RTK:** 이 작업은 셸 출력이 작아서 판단할 수 없습니다(+3%, 오차 범위). 아래 2번 측정을 보세요.

### 2. RTK 중심 (2026-10-08)

- 모델 sonnet, 조건 A·B × 5회, 저장소 `rtk-ai/rtk` 클론(커밋 2,275개)
- 작업: "git log -50 --stat 결과를 보고 최근 변경 경향을 5줄로 요약해 줘. 파일은 수정하지 마."

| 조건 | 환산비용* | 컨텍스트 | 출력 | 턴 | 비용($, 참고) |
|---|---|---|---|---|---|
| A 기준 | 17,984 | 128,136 | 1,034 | 2.2 | 0.2064 |
| B RTK | 18,685 (+4%) | 134,839 (+5%) | 1,040 (+1%) | 2.4 | 0.1737 |

- **결과:** RTK 효과가 없었습니다(+4%). 2턴으로 끝난 회차는 A와 B의 캐시 쓰기 토큰이 거의 같았습니다(36,659 vs 36,655). B가 조금 높게 나온 것은 3턴짜리 회차가 더 많았기 때문입니다(A 1회, B 2회).
- **이유:** 모델이 실제로 실행한 명령은 `git log -50 --stat --format='…' | head -400`처럼 옵션과 파이프가 붙은 형태였습니다(세션 기록으로 확인). RTK는 아래처럼 `--stat`이 붙은 `git log`를 줄이지 않습니다. 그래서 이 작업에서는 줄일 출력이 없었습니다.

**명령별 RTK 출력 감소** (같은 저장소, `rtk proxy <명령>`(원본)과 `rtk <명령>` 출력 바이트 비교):

| 명령 | 원본 | RTK | 변화 |
|---|---|---|---|
| `git log -50` | 29,889 | 12,231 | **−59%** |
| `ls -la src` | 618 | 125 | **−80%** |
| `git show HEAD` | 1,340 | 1,167 | −13% |
| `git log -50 --stat` | 37,808 | 37,808 | 0% |
| `git log -50 --oneline` | 3,688 | 3,688 | 0% |
| `git diff HEAD~20 --stat` | 5,526 | 5,526 | 0% |

- RTK는 일부 명령의 **기본 형태**만 크게 줄입니다. 이미 간결한 옵션(`--oneline`, `--stat`)이 붙으면 그대로 내보냅니다.
- 에이전트는 명령에 옵션·파이프(`| head`)를 붙여 스스로 출력을 줄이는 경우가 많습니다. 이 경우 RTK가 줄일 여지가 작습니다. 앞서 확인했듯 `;`로 이어 붙인 뒤쪽 명령은 RTK가 바꾸지 않기도 했습니다.
- **정리:** 이 측정 기준으로 RTK의 비용 효과는 **없음**입니다. JetBrains 측정(high 설정 ±0%)과도 같은 방향입니다. 테스트 실행처럼 기본 형태의 긴 출력이 반복되는 작업에서는 다를 수 있습니다. 측정 안 함. [UNKNOWN]

### 종합 (2026-10-08 기준)

| 도구 | 출력 토큰 | 실제 효과 (환산비용) | 판단 |
|---|---|---|---|
| Caveman 스킬 | −30% | **약 −7%** | 작지만 일관된 절약. 품질 문제는 보이지 않음 |

두 도구 모두 비용의 대부분인 **컨텍스트**(매 턴 다시 읽는 대화)는 줄이지 못합니다. 더 큰 절약은 세션을 짧게 끊기(`/clear`), 상시 로딩 지시문 줄이기 같은 컨텍스트 관리에서 나옵니다.
